End-to-End Mental Model

Service → WidgetModel → Widget.render() ↓ WidgetContent → WidgetLayout → WidgetView ↓ DashboardSnapshot + WidgetPlacement ↓ Console / Dev Web / SwiftCrossUI renderer ↓ User action name → DashboardRunner.perform → InteractiveWidget

The framework moves data toward renderers as immutable semantic snapshots. Input travels back as widget ID plus action name.

Reading Priority

Must Know Read Package.swift, Dashboard.swift, DashboardRunner.swift, Widget.swift, WidgetContent.swift, and Composition.swift.

Important Read the renderer model, board column DSL, and one service-backed widget end to end.

Optional Read GTK-specific support and Pi deployment scripts only when changing native UI or the appliance.

Remember Only 3 Things

  1. The Framework/Renderers/App separation is the organizing principle.
  2. Widgets emit semantic content; renderers decide pixels and platform behavior.
  3. The live Pi app is both a product and the integration proving ground for the library.
