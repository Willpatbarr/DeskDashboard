DeskDashboard / Codebase Guide

Application, Widgets, and Ingestion

The App layer provides six feature families, ten widget instances, and Pi-specific ingestion and operations.

Composition Root

makeDeskDashboardSystem() in DeskDashboardComposition/Composition.swift creates services, the dashboard, widgets, the runner, and ingest-capable state. Start there to see what runs.

Service-Backed Widget Pattern

Service protocol + ServiceKey → concrete real/push/simulated service → WidgetModel activates and reads service → Widget renders WidgetContent from model state → selected WidgetLayout produces WidgetView

Fallback services keep widgets usable in development. Direct widget binding overrides the dashboard environment; environment registration overrides the fallback.

Push Ingestion

DeskDashboardIngest/PushIngest.swift defines app-specific HTTP routes for pushed indoor-temperature and now-playing data. registerPushIngest wires those routes to shared stores.

Both the dev executable and native UI can run the same ingest server, normally on port 8642.

The HTTP layer has no TLS or authentication and is intended for trusted local-network use. Do not expose it directly to the public internet.

Executable Entry Points

deskdashboard-dev

Dependency-light development executable using console or web rendering. This is the static-musl cross-compile path.

deskdashboard-ui

Native SwiftCrossUI/GTK appliance. It parses kiosk, scale, window, slide, and frame options before launching the renderer.

Arrangements and Boards

Arrangements.swift defines the selectable presentation catalog. Board extensions such as FocusBoard, MTGBoard, RuledBoard, EqualWidthsBoard, and WideClockBoard define concrete geometry with renderer-owned board primitives.

The background image path is currently machine-specific. Treat resource ownership as app configuration or a declared SwiftPM resource rather than a hard-coded filesystem assumption.

How to Add a Widget

  1. Define a service protocol and typed ServiceKey.
  2. Add a real, push, local, or simulated service implementation.
  3. Create a WidgetModel for activation, updates, ticks, and deactivation.
  4. Create a ServiceBackedWidget and render WidgetContent.
  5. Choose or add a WidgetLayout using semantic WidgetView nodes.
  6. Register the service and widget in Composition.swift.
  7. Add focused model/widget tests and verify the live board.
