Run DeskDashboard Locally

Use console for logic, browser for fast visuals, or native UI for renderer behavior.

Choose a mode

Fastest

Console

Data and lifecycle only.

swift run deskdashboard-dev --console
Best default

Browser

Visual preview and ingest.

swift run deskdashboard-dev
Real renderer

Native window

SwiftCrossUI behavior.

swift run deskdashboard-ui --window 1920x440

Browser

1

Start it

swift run deskdashboard-dev
2

Open the page

http://127.0.0.1:8642

3

Optional: change the port

swift run deskdashboard-dev --port 9000

Native UI

1

Use the panel geometry

swift run deskdashboard-ui --window 1920x440
2

Keep the layout switcher

Omit --kiosk; it hides the switcher.

3

Adjust scale

DD_UI_SCALE=1.1 swift run deskdashboard-ui --window 1920x440

Push test

Run the web or native UI, then POST to port 8642.

curl -X POST http://127.0.0.1:8642/ingest/now-playing \
  -H 'Content-Type: application/json' \
  -d '{"title":"Test Track","artist":"Test Artist","isPlaying":true}'

For payload changes, use the JSON shape in the ingest tests or producer.

Troubleshoot

Port busy

Use --port N, or stop the process already using 8642.

Native build fails

Use deskdashboard-dev to avoid GUI dependencies.

Push is invisible

POST to the process displaying the dashboard.

Mode summary

  • Console: data.
  • Browser: semantic layout.
  • Native UI: renderer behavior.

Done when

The renderer stays running, the dashboard updates, and the test POST changes the intended tile.
