Install, Inspect, and Recover the Pi Kiosk

One-sentence version: Install once, switch to console boot before enabling, and use systemd plus Sway-aware checks for daily operation.

Source checkedLow-reading layout360px ready

First Installation

1

Build the UI first

CONFIG=release JOBS=1 bash scripts/build-ui-pi.sh
2

Install the service

sudo bash scripts/install-kiosk-pi.sh
3

Free the display

sudo raspi-config nonint do_boot_behaviour B2
4

Enable, then reboot

sudo systemctl enable deskdashboard-ui
sudo reboot
Stop

Do not start Cage while the desktop owns the display. Switch to console boot first.

Daily Commands

Restart

sudo systemctl restart deskdashboard-ui

Status

systemctl status deskdashboard-ui

Boot log

journalctl -u deskdashboard-ui -b

Whole-system UI log

journalctl --since '-5min' --no-pager | grep -i deskdashboard

The current app is exec’d by Sway, so some stderr appears under Sway rather than under the systemd unit.

Take a Screenshot over SSH

1

Capture with grim

export XDG_RUNTIME_DIR=/run/user/$(id -u)
export WAYLAND_DISPLAY=$(basename $(ls $XDG_RUNTIME_DIR/wayland-* | grep -v '\.lock' | head -1))
grim /tmp/dash.png
2

Copy it to your Mac

scp willbarr@192.168.4.244:/tmp/dash.png .

Bring Up the Whole System from the Mac

Kick local producers, SSH to the Pi, restart the kiosk, and print status:

bash scripts/start-dashboard.sh

Override the host if needed:

PI_HOST=user@pi-address bash scripts/start-dashboard.sh

Return to the Normal Desktop

Recovery
sudo systemctl disable --now deskdashboard-ui
sudo raspi-config nonint do_boot_behaviour B4
sudo reboot

Remember Only 3 Things

  1. Never let the desktop and the kiosk compositor fight for the display.
  2. Systemd owns restart policy, but Sway currently owns the actual binary command.
  3. Rollback is disable service → restore desktop autologin → reboot.
