Build the Real UI on Raspberry Pi

Install GTK once, build deskdashboard-ui natively on the Pi with one job, then restart the kiosk.

Build Path

deskdashboard-dev→static-musl cross-build is OK
deskdashboard-ui→GTK + glibc→build natively on Pi

The GTK UI cannot use static musl.

One-Time Pi Setup

1

Install native dependencies

sudo apt update
sudo apt install -y libgtk-4-dev clang pkg-config
2

Confirm Swift is on PATH

swift --version
pkg-config --modversion gtk4

Build

1

Enter the Pi checkout

cd ~/Desktop/DeskDashboard-MacMiniDev
2

Build release with one job

CONFIG=release JOBS=1 bash scripts/build-ui-pi.sh
3

Confirm the output path

built: …/.build/release/deskdashboard-ui

The kiosk launches the release binary from ~/.config/sway/kiosk.conf; a debug build will not appear.

Restart and Verify

1

Restart

sudo systemctl restart deskdashboard-ui
2

Check status

systemctl is-active deskdashboard-ui
systemctl --no-pager -n 20 status deskdashboard-ui
3

Check the actual launch path

grep -n 'deskdashboard-ui' ~/.config/sway/kiosk.conf

Resource Limits

  • Use JOBS=1 on the 4 GB Pi.
  • Release builds are slow.
  • Never delete .build during a build.
  • Check dependency-patch warnings.

Key Facts

Ship the native glibc + GTK release binary. Deployment requires the active Sway config and a service restart.

Done When

  • The build prints the release path.
  • The service is active.
  • The panel shows the change.
