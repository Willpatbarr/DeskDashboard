Widget Contracts

Widget

Base lifecycle contract with chainable modifiers for identity, title, size, priority, visibility, refresh, tile layout, and chrome.

RenderableWidget

Adds render(environment:) and returns semantic WidgetContent.

ServiceBackedWidget

Resolves a directly bound service, environment service, or fallback; owns model activation and teardown.

InteractiveWidget

Receives string action names emitted by renderer-interpreted WidgetView nodes.

A service-backed widget should normally implement configuration, service key, bound service, model storage, model/fallback factories, and render.

Semantic Rendering Model

WidgetView is an indirect enum containing text roles, badges, spacers, stacks, centered groups, dividers, progress, play state, fitted text, tappable nodes, and minimum-size regions.

Must Know

Widgets do not choose fonts or pixels. They choose semantic roles and structure; renderer plus theme determines actual presentation.

WidgetLayout is an Equatable/Sendable named mapping from WidgetContent to WidgetView. Sixteen preset layouts live under Widget/Layouts.

Dashboard recomputes placement after additions, removals, and applied layout changes.

Theme System

Theme is Sendable and supplies sizes, colors, typography, spacing, shape, animation, and a default layout. ThemeMetrics converts design tokens for a viewport.

Built-in themes

DefaultTheme, DarkDeskTheme, GreenBoardTheme, GradientClockTheme, and RuledGreenTheme.

Token groups

ThemeSizes, ThemeColors, ThemeTypography, ThemeSpacing, ThemeShape, and ThemeAnimation.

Clock and Refresh

DashboardClock abstracts start/stop state. ManualDashboardClock makes time deterministic in tests; TimerDashboardClock drives production ticks.

RefreshRate stores seconds. Dashboard-level rate drives the clock, while each widget may impose a slower delivery interval.

Core Risks and Extension Rules

  • DashboardRunner has mutable state without an explicit actor contract.
  • Configuration and environment use String/Any storage behind typed keys.
  • DashboardRenderer's default run method can own the main run loop.
  • Preset tile layouts may be product-specific API commitments if left in core.
  • WidgetContent has no renderer-neutral image/media descriptor yet.

Prefer extending semantic types over adding backend-specific cases. Keep App services and business rules outside DashboardKit.

Remember Only 3 Things

  1. Dashboard is the state machine; DashboardRunner is the clock-driven reference wrapper.
  2. ServiceBackedWidget removes repeated service/model lifecycle code.
  3. WidgetLayout converts content into backend-neutral WidgetView structure.

What To Do Next

  1. Read Dashboard.swift before changing lifecycle behavior.
  2. Add ManualDashboardClock tests for timing changes.
  3. Treat new public symbols as future compatibility commitments.
